# v0.3.4

Range: `v0.3.3`..`v0.3.4`.

## macOS (testing)

- Native GOG builds only (decision #836): `decanter_core::platform::game_system()` returns `GameSystem::MacOs` on macOS, `GameSystem::Windows` on Linux and Windows. `GameSystem` is exported from `decanter_core` and prints `macOS` or `Windows`.
- `Feature::Play` goes from `Unavailable` to `Testing`; `Tray` and `CloseToTray` stay `Testing`. `PsSection` is `Unavailable(Reason::NotPortedYet(Source::Psport))`; `PsBuilds`, `PsDownloads`, `PsPlay`, `PsMenuBinding`, `PsKeyStick`, `PsOnline`, `MangoHud`, `GameMode` stay `NotOnThisSystem`.
- Launch backend: `cfg(proton)` is set only when `CARGO_CFG_TARGET_OS` is `linux` (`app/build.rs`, `crates/runtime/build.rs`), so macOS builds `decanter_runtime::native`, now `native/{mod,windows,macos}.rs`.
- `native/macos.rs`: the game starts as leader of its own process group (`Command::process_group(0)`); `Tracked::remaining` polls `killpg(group, None)` (`ESRCH` ends the session); `close` sends `killpg` SIGTERM, or SIGKILL when forced. `Group::led_by` takes only pids above `INIT_PID = 1`. A process that leaves the group (`setsid`, `setpgid`) leaves the session.
- Install: `depot::get_builds`, `select_depots`, `plan`, `resolve_depot_files`, `dlc_only_files`, `verify` and `repair` take a `GameSystem`. The builds URL is `content-system.gog.com/products/<id>/os/{windows|osx}/builds?generation=2` (`os_segment`); `Error::NoBuilds(GameSystem)` names the system. `DepotMeta::is_compatible` keeps the bitness filter for Windows only.
- Files whose `DepotFile::flags` holds `executable` get `executable_permissions()` (mode `0o755`) after writing (`PlannedFile::is_executable`, only for `GameSystem::MacOs`); `repair` also restores the bundle program's mode (`program::bundle_program`).
- Launch executable (`install::program::find_bundle_executable`): the shallowest `Contents/Info.plist` at the install root or under a `*.app` folder, `CFBundleExecutable` read with `plist` 1.10.3 (decision #892; default features off, new in `Cargo.toml`), giving `<bundle>Contents/MacOS/<name>`. The plist must be a regular file (no symlink) of at most `INFO_PLIST_MAX_BYTES = 1 MiB`; the name must be a plain file name present among the installed files. Falls back to `goggame-<id>.info`.
- `app/src/launch/native.rs`: the achievement log (`decanter-hook`) and the DirectX 7 hint after a failed run apply only when `game_system()` is `Windows`.
- Cloud saves: `UserFolders` holds `folders: Vec<(&str, PathBuf)>`, `galaxy_storage` and `system`. macOS: `DOCUMENTS` and `APPLICATION_SUPPORT` (`dirs::data_dir`, `~/Library/Application Support`), with Galaxy's default `GOG.com/Galaxy/Applications/<client id>/Storage` under it. `RemoteConfigContent` reads `Windows` and `MacOS` as optional sections; a missing one for the system means no cloud saves. `crates/gog` takes `dirs` on `cfg(any(windows, target_os = "macos"))`.
- `docs/macos-support.md` (new).
- Untested: nothing here has run on a Mac. macOS clippy was run with a stand-in C compiler, not Apple's toolchain.

## library

- `Game::has_macos_build: Option<bool>` is read from `content_system_compatibility.osx` of GOG's product record (`product::ContentSystems`, `bool_or_none`: any non-boolean reads as unknown) in `library::enrich::apply_product_facts`.
- `Game::has_build_for(GameSystem)`: Windows always true; macOS true unless `has_macos_build == Some(false)`. `views::library::actions::missing_build` shows `library.detail.no_build` ("This game has no macOS version") in the detail bar and the context menu in place of Instalar and Jugar.
- Stored data, additive: column `games_cache.has_macos_build INTEGER` (`NULL` = unknown), added by `ALTER TABLE` when `has_column` says it is missing; `CachedGame::has_macos_build` upserts with `COALESCE`, so a fetch without it keeps the stored value. Existing columns, the CLI and `libraries.toml` are unchanged.

## Windows (testing)

- `Feature::SteamExport`, `PsSection` and `PsPlay` go from `Unavailable` to `Testing`; `PsBuilds` is `Unavailable`. `Feature::ALL` 20 -> 21 with `PsBuilds` (port checkout, toolchain, prebuilt and released builds, and what runs inside them), unavailable on Windows and macOS.
- Close-game shortcut (`app/src/platform/close_hotkey.rs`, used on Windows and macOS): the press posts a GPUI `SystemNotification` tagged `NOTICE_TAG = "decanter-close-game"` (`closing.notice.title`, `body_keyboard`, `cancelled`), dismissed on stop. `CloseWatch::open` takes the `AsyncApp`; the notice is posted from the main thread.
- Steam export: `steam_root_candidates` yields `SteamPath` under `HKCU\Software\Valve\Steam` (read with `reg query`, absolute paths only), then `%ProgramFiles(x86)%\Steam` and `%ProgramFiles%\Steam`. `steam::process::state` asks `tasklist /FI "IMAGENAME eq steam.exe"` (`Running`, `NotRunning`, `Unknown` when it fails); the fallback launcher is `steam.exe` (`LAUNCHER`). Child console programs start with `CREATE_NO_WINDOW` (`0x0800_0000`, `platform::without_console`).
- Untested: nothing has run on a real Windows; the tray, the close shortcut, the Steam export and PS play stay `Testing`.

## app

- PS section on every system: the nav link is always shown (`Caps::mark` replaces `gate`, marking `Testing` and keeping `Unavailable` visible); where `PsSection` is not offered `views::ps::unsupported` shows `ps.unsupported.title` and the reason, and `PsView` is never built (`Shell`). `Reason::NotPortedYet(Source)` reads `common.not_ported_yet_ps` ("psport doesn't support %{system} yet"; `system_name`: `macOS`, `Windows`, `Linux`). Linux is unchanged.
- The PS update loop starts only when `Feature::PsBuilds` is offered (`state::ps::Ps::new`).

## ps

- Direct launch on Windows (`platform::DIRECT_LAUNCH`: `true` on Windows, `false` on Linux and macOS): `crates/ps/src/bbport/direct.rs` and `app/src/state/ps/direct.rs` (`cfg(windows)`).
- Setting `psport_exe_dir` (`direct::FOLDER_KEY`, `LauncherSettings`, optional) is picked in PS > Ajustes (`ps.settings.psport_folder.*`). `Folder::try_new` rejects (`FolderError`): a relative path or one with `..`; a path off a local drive (`Prefix::Disk` or `VerbatimDisk` only, also after `canonicalize`); a non-folder; `psport.exe` or `libpsport-gpu.dll` missing or a symlink. Checked when picked and at each launch.
- `Bbport::direct_command`: `game_env` (split out of `launch_command`, which now takes `GameLaunch<'_>`) plus `direct::run_sh_defaults` (`PS_CONFIG`, `PS_GPU_USER_DIR`, `PS_COPY_GPU_BUFFERS=1`, `PS_GPU_WRITE_TWINS=1`, `PS_GPU_WRITE_TWINS_MAX=65536`, each only when unset or empty) and `direct::arguments` (`--game`, `--system-modules`/`--hle`/`--lle`, `--mods`/`--mods-config`/`--out`, `--patches-dir`, `--patches-config`, `--app0`, `--user`, `--timeout`, as `run.sh` builds them; a path starting with `-` is prefixed with `./`). No Nix, bash or `run.sh`.
- The game runs in a `decanter_runtime` session (Job Object) through `Launcher::Session`; stop is `decanter_runtime::stop` on the key `ps:<dump dir>`. Only `Port::Bbport` runs this way; other ports fail with `ps.play.direct.port_unavailable`. `Names::of_script` and `is_single_memory_model` assume a current port when `DIRECT_LAUNCH`.
- `ps.errors.builds_unavailable` and the Ports, builds and channels views show why they are off (`PsBuilds`).

## Compatibility

- No breaking change: stored data is only extended (`games_cache.has_macos_build`, guarded by `has_column`; optional setting `psport_exe_dir`), the CLI and `libraries.toml` are untouched, no existing setting changes meaning.
