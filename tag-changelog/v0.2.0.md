# v0.2.0

Range: `572dacf` (0.1.2, untagged)..`v0.2.0`.

## ps

- New crate `crates/ps` (`decanter-ps`): PS4/PS5 dumps run through two ports, `port::Port::{Bbport, AnyPs5}`; upstreams `deadinside28/bloodborne_pc` and `boykopovar/AnyPS5`, checkouts in `<library>/psport/ports/{bbport,anyps5}`.
- `paths`: all PS data under `<library>/psport/` (`games/`, `toolchain/`, `bbport/` as `BB_DATA_DIR`, `anyps5/`, `backups/`, `fsr4_411/`, `profiles/<id>/`, `layouts.json`); `paths::use_library` repoints it on profile switch.
- PS games are read only from `<library>/psport/games`; `ps_scan_dirs` table dropped (`DROP TABLE IF EXISTS`).
- `toolchain`: host tools, else system `nix-shell` (`/nix/var/nix/profiles/default/bin/nix-shell`, `~/.nix-profile/bin/nix-shell` fallbacks), else `toolchain::portable` nix-portable `v012` (SHA-256 checked); nixpkgs pinned in `toolchain/pkgs.nix` (`39ad350a`).
- `updater`: clones and fast-forwards each port checkout; `Plan::{Rewritten, LocalCommits}` wait for the user, and a reset saves the local diff to `backups/` first.
- `process`: ports, builds and conversions run as tokio jobs with streamed output, capped at `MAX_LINES = 5000`.
- `library::scan`: dump discovery, not cached; `status::classify` reports what blocks play (missing update, encrypted executable).
- `bbport`: Bloodborne `SUPPORTED_TITLE = "CUSA03173"`, `SUPPORTED_VERSION = "01.09"`; `merge_update` builds `<base>-<version>` from hard links plus the update.
- `anyps5`: shared conversion in `anyps5/<TITLE_ID>/` (`app.elf`, `libs/`, `app0/`, `anyps5-input.ini`); per-profile run directory with its own `_sd/`.
- `failures`: faults, `STOP:` lines, errors and bad exits kept in the profile's `failures.jsonl` (`MAX_RECORDS = 500`, 15 lines before / 25 after), copyable as reports.
- `mapping`: `anyps5-input.ini` parser/renderer shared by both ports (27 `Action`s).
- `layouts`: named gamepad (bbport) and keyboard (per port) layouts in `layouts.json`; built-in ones are never written.
- `bbport::tools`: mods, external patches (`mods.json`, `patches.json`) via bbport's own Python helpers; FSR 4.1.1 built from the user's AMD DLL into `fsr4_411/` (`BB_FSR411_DIR`).
- `bbport::icons`: button glyphs (`IconStyle::{Ps, Abxy, Bayx}`) written into `dvdroot_ps4/menu/common.tpf.dcx` and loaded as decanter's own mod `zz-decanter-iconos`, last in load order.
- App: `views::ps` section (tabs Juegos, Ports, Fallos, Ajustes) on every profile, between Biblioteca and Almacenamiento; profile kind removed.

## library

- External games (`app/src/external`): filed under the profile id with a uuid game id, launched through the GOG runner with their own prefix and Proton pin; added from Biblioteca (`views::external`), replacing the Ajustes "Externos" tab.
- `external::art`: art from SteamGridDB (API key in the keyring, account `steamgriddb`) then Steam store art; kept in the manifest's `Art` block (`decanter_core::GameArt { cover, hero, icon }`).
- `external::import`: imports a game from another tool's Wine prefix into the profile's `compatdata`, moved or copied; `external::transfer` copies with rsync when present into `.<name>.partial`, renamed into place once complete; leftover staging dirs are deleted.
- `decanter_core::move_dir`: rename, else copy keeping symlinks as links, source removed only after the copy; `Library::move_to` uses it.
- `Db::forget_product`: deleting an external game drops its favorites, hidden flag, playtime, caches, Steam shortcut row and collection membership.

## runtime

- External games launch as `umu-default` with no `STORE` unless a UMU database entry is picked (`external::umu`, read from the newest Proton's `protonfixes/umu-database.csv`, else fetched); kept in the manifest as `UmuId`/`UmuStore`.
- `strip_launcher_env`: drops `VK_DRIVER_FILES`/`VK_ICD_FILENAMES` when they name `/nix/store/`, so launched games use the host's Vulkan drivers.
