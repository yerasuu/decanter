# v0.4.0

Range: `v0.3.4`..`v0.4.0`.

## BREAKING CHANGE

Both breaks are in components first added inside this range (`crates/report` and `crates/reports-server` are not in the `v0.3.4` tree), so nothing written by a release up to `v0.3.4` is affected; they break the intermediate `develop` snapshots and anyone who deployed or integrated one.

- Reports server (`2f5c4bd`): the single admin key is gone. `Config` is `deny_unknown_fields`, so a config with `admin_key`, `admin_key_file` or `admin_key_env` no longer loads. Remove those keys. Admin access stays off (every `/admin` path answers the uniform 404 and the log warns hourly) until an account exists: create one with `decanter-reports user add <name> --role admin` (the config path comes from `DECANTER_REPORTS_CONFIG`), keep the `drk_<id>_<hex>` key it prints on standard output, and log in at `/admin/login` with it. `decanter-reports secret` prints a 64-hex passphrase for the new encrypted `accounts/` store's partition setup.
- Error-report schema 2 (`3909465`): `decanter_report::SCHEMA` goes 1 -> 2. `failure.message` was free text; it is now an object `Message { template, slots, cause }` (template id of the closed vocabulary plus typed `Slot`s), and is absent when no template matches. `validate` refuses any report whose `schema` is not `SCHEMA`, so a client of schema 1 is refused by the server. `psport_report` and `decanter_report` take `&Identity` (`user`, `host`, `home_dirs`, `account_names`, `display_names`, `pad_names`, `extra`) and return `Err(Vec<Rejection>)` for any text or field that holds one of its strings. Integrators must send schema 2 and pass the client's identity to the builders.

## Stored data and layout

- `decanter.db`: `PRAGMA user_version` is stamped to `SCHEMA_VERSION = 2` once `Db::open` has migrated a file, and a file already at it skips the migration (it took the write lock on every open). New table `game_language (account_id, storefront, product_id, language)`, primary key the first three, made by `CREATE TABLE IF NOT EXISTS`. New settings keys `resume_downloads_on_start` (absent = on), `raven_enabled` (absent = off), `report_server`.
- Library manifests (Steam-format `appmanifest`): optional `Language` key, the storefront tag of the one language installed (`InstalledGame::language`); absent means every language, as installs before this version read.
- `<root>/downloading/<account>/<product>/`: `download.json` (journal header, `FORMAT = 1`), `progress.log` (CRC-32 per line, torn tail cut on open; `progress.log.new` while a new build's log is swapped in), `lock`, `pending.json` (`FORMAT = 1`), `files/<path>.part`. Beside them `<root>/downloading/queue.json` (`FORMAT = 1`, the order of the queue) and `<root>/downloading/lock` (the one download slot across processes). Folders with no `download.json` left by older versions are listed in Storage.
- Secrets: one store, `decanter_core::secrets` (replaces `credentials.rs`), over `keyring-core` with service `dev.decanter.Decanter` and the same entry names. With the keyring missing or locked, `<config>/decanter/secrets.bin` (magic `DCNTSEC\0`, `FORMAT = 1`, Argon2id 256 MiB t=6 p=1, XChaCha20-Poly1305, `0600` in a `0700` folder). Migration on use: the SteamGridDB key moves to `steamgriddb/api_key`; the launcher's plaintext `online_password` in the port's `settings.json` moves into the keyring (kept in the file when there is no store); each old copy is removed only after the new one reads back; Windows entries become `Local`; `delete_profile` deletes the profile's GOG sessions.
- File modes: on Unix `decanter.db`, day logs, report files, run logs and the debug folder are created `0600`/`0700` (`decanter_core::private`), older ones narrowed once at startup; `sent.jsonl` is restricted with `icacls` on Windows. Temp folders of umu-run and artwork are random `0700` folders under `XDG_RUNTIME_DIR` when set.
- PS per-game settings (`docs/ps-per-game-settings.md`), under `<library>/psport/`: `titles/<TITLE_ID>/settings.json` (`format: 3`, `created_from`, `created_on`), `titles/<TITLE_ID>/psport.ini` (passed as `PS_CONFIG`), `titles/<TITLE_ID>/{mods.json,patches.json,mods-effective}` and the title's mods/patches folders, `defaults/settings.json` and `defaults/psport.ini` (the template a new title copies once), and `layouts/<pad|bbport-keys|anyps5-keys>/<id>.json` (one file per layout, `pad_layout`/`key_layout` per game). Each is made once from the shared files after a copy into `backups/per-game-settings-<date>/` (the copy leaves out keys matching `redact::is_secret_name` and the secret `extra_env`); the shared `settings.json` is then trimmed to the keys it still owns (`SHARED`: shadNet account and server addresses, `sys_modules_dir`, `sys_fonts_dir`, `psport_exe_dir`, the Windows package choice) and the former launcher's unread keys (`ui_language`, `game_dir`, `user_dir`, `mangohud`) go. `layouts.json` is left as it was. Only the allow-list stays shared; a key added later is per game. Older ports without `PS_CONFIG` keep the shared files.
- Per-game keys: `online`, `online_upnp`, `online_bbsc`, `online_bbsc_local_server`, `online_tls`, `online_allow_plaintext` (absent = on), `sys_modules`, `frame_gen` (`off`|`fsr`), `local_player` (1 to 10, Bloodborne).
- Settings export file: `kind = "decanter-ps-settings"`, `VERSION = 1`, at most 256 KiB (`transfer::MAX_BYTES`), checked whole against an allow-list on import.
- Added folders under the library root: `decanter/mods/<store>/<game>/` (`mod.toml`, `profiles/<account>.toml`, `play/<account>/`), `decanter/redist/` (`redist.json`) and `<prefix>/decanter-redist.json`, `decanter/runners/ge-proton/<tag>/`, `decanter/bin/path/umu-run`, `decanter/runners/raven/`, `decanter/reports/sent.jsonl`; `<data dir>/gog-mods.json` (24 h cache of GOG's mod catalog, at most 4 MiB). Cloud saves are written to `.decanter-tmp-<uuid>` beside the destination and renamed.
- `$XDG_DATA_HOME/dev.decanter.Decanter/` (`Decanter-x86_64.AppImage`, `version`): decanter's own copy of the AppImage, where updates go when the started AppImage sits in a folder that is not writable.
- `libraries.toml`: same keys; a UTF-8 BOM is now stripped on read (`decanter_core::bom`), as for hand-edited PS JSON and TOML. A profile's library path equal to the library holding its database is unset at startup, after a library move and on profile creation.
- Not changed: the `games_cache` columns, the `libraries.toml` schema, the GOG session JSON (`Token` wraps its tokens at the serde boundary, byte-identical).

## CLI

- `decanter install` gains `--language <tag>` (GOG tag such as `es-ES`; without it a new install takes the game's saved language, else the app's, an installed game keeps its own) and `--no-wait` (exit at once when another decanter process downloads, instead of waiting for the one slot; the wait says so every 15 s). `install::Target` replaces its positional arguments.
- `decanter ps` (new): `run --title <ID> [--timeout <1..604800>] [--env PS_NAME=VALUE]...`, `prepare [--port psport|anyps5] [--timeout]`, `settings list|get|set|copy|reset|forget|export|import`, `report`. Exit codes of `run` and `prepare`: 0 clean, 1 failure or timeout, 2 not started (`ps_run::NOT_STARTED`); other commands keep 1 for errors, and `dispatch` now returns the process exit code. `ps settings` takes `--title <ID>` or `--title defaults`; `copy` takes `--from`, `--title` or `--to all`, `--category`; `copy`, `reset`, `forget` and `import` need `--yes`; exits 0 done, 1 file error, 2 refused.
- `ps run` uses only a port already built, never connects online (`--env` refuses the 12 `ONLINE_VARS`; names are `PS_` plus up to 64 of `A-Z0-9_`, values up to 256 printable ASCII, at most 32 pairs), and on Windows starts the psport.exe Play would, in its Job Object session.
- `ps report [--product psport|decanter] [--title <ID>] [--failure N] [--day YYYY-MM-DD] [--print|--out <file>] [--send --yes [--attach-log]] [--sent] [--delete <ID> --yes]`: builds a closed report from a local failure (`failures.jsonl` or the day log); `--send` is the only way a report leaves, `--attach-log` without `--yes` is a dry run that prints the scrub counts and log size. `--server` is hidden.
- Windows: `decanter.exe` is built for the GUI subsystem; `decanter-cli.exe` (`--features decanter/windows-cli`, `app/src/cli_shim.rs`) runs it with the same arguments and exit status.
- Reports server: `decanter-reports user add <name> --role viewer|admin [--force-reuse] | list | remove <name> | reset <name> | role <name> --role ...`, `secret`, `inspect <product> ls|get`, `--check-config` (one line per partition).

## gog

- Downloads: a journal per download (`install::journal`, `FORMAT = 1`), commit every `COMMIT_BYTES = 64 MiB` (or 5 s), `.part` files renamed when complete, 60 s retry window; `PauseReason` is `User`, `Network`, `AppClosed`, `ClosedUnexpectedly`, `DiskFull`, `LibraryUnavailable`. After an unclean exit a resume keeps every chunk past the last record whose size and MD5 match. A new build at resume keeps each file's leading chunks both builds share (`BuildSwitch`). Little free space or `ENOSPC` pauses as disk full with the room needed (`Room`).
- Queue (`install::queue`): one download at a time across processes (`download_slot_busy`), explicit order with `QueueMove::{Up, Down, First, Last, To}` kept in `queue.json`; a queued or planning download records `pending.json` so pause, cancel and quit need no GOG plan; DLC ticked with a game are queued as downloads of their own, held back until the game lands.
- `unfinished::resume` and `resume_repair` plan again from the journal's request; every update, DLC, branch switch and repair goes through `install::track` and is listed and cancellable.
- Integrity: every chunk's `compressedMd5`, `md5` and size are checked as it downloads (a mismatch is a failed try, then the install fails naming the file); chunk errors and `ChunkSource` `Debug` drop the signed URL; cloud saves are written atomically; a renewed token of another account is `Error::Rejected`; the cloud-saves token request is URL-encoded.
- Manifest links: https on `gog.com`, or a `gog-cdn-*` host at `gcdn.co` (no access token sent there).
- Language: `select_depots` keeps `*` depots and those of the one tag resolved from the wanted list (exact, same language, then `en-US`); the tag is in the journal, plan hash, manifest and `goggame-<id>.info`; `add_language` and `remove_unused_languages` change it later; a DLC with no depot is installed as an entitlement; a path shipped by several depots is planned once (the later depot wins).
- Redistributables: builds' `dependencies` are fetched into `<root>/decanter/redist` and run once per prefix before launch (`install::redist`); the properties' General tab picks among the `FileTasks` of `goggame-<id>.info`, kept across updates.
- Mods: `decanter_gog::mods` reads GOG's catalog of products tagged `mod` (`Sessionless::catalog_mods`) into `gog-mods.json`, marks owned ones and links the rest; loose-folder mods are the `decanter-mods` crate (see library).
- API client: `decanter_gog::api::client` (async, `reqwest` 0.13, typed `Error`, one token lock per account) replaces the blocking `gog` 0.5.0 client; the four files that derived from it were rewritten from `docs/gog-api-behaviour-spec.md`. Redirects only between GOG hosts, the answer must come from the host asked, product ids positive, "no builds" is an empty list. `with_session` is gone; calls take `session::live_token`.
- Performance: filtered-products pages are fetched three at a time.

## library

- Mods (`crates/mods`, `docs/mods.md`): add a folder, enable, conflicts, remove, in a Mods tab; the game starts from a play tree of relative links (hard links on Windows hosts), so verify, repair and update see only `common/<InstallDir>`.
- External games: dropping an executable (PE, ELF, AppImage, `#!` script) adds one with its name and icon read from it (bounded reads, checked offsets), with Editar and Deshacer for the whole drop; Linux programs run natively, tracked and stopped by `DECANTER_SESSION`, and get the exec bit at launch.
- `copy_dir` and `transfer::bring` take a stop flag (`io::ErrorKind::Interrupted`); a move checks the copy's size before removing the original; the prefix import has Cancel.
- Profile library paths that name their own library are unset (see stored data).

## ps

- Per-game settings, defaults, copy, reset, forget, export and import: see stored data and CLI; the app has a defaults page in PS Ajustes and Copy, Export, Import, Reset in a game's Resumen. Online tab only for dumps whose eboot names an NP matchmaking or session library (`online_support::SCAN_VERSION = 3`, cached by size and mtime); online support is hidden where the system has none (`PsOnline`).
- Online: per-game `online_tls` (`PS_SHADNET_TLS=1`) and `online_allow_plaintext` (`PS_ONLINE_ALLOW_PLAINTEXT_LOGIN=1`); builds listing `secrets_handoff` get `PS_SHADNET_SECRETS_FILE` (one-use `0600` file in `XDG_RUNTIME_DIR`, Linux) or `PS_SHADNET_SECRETS=stdin` (Windows) instead of `PS_SHADNET_PASSWORD`/`PS_SHADNET_TOKEN`; a 4xx from the game server counts as an answer in the connection test.
- Frame generation: per-game `frame_gen` (`PS_FRAME_GEN` always passed when the build lists the row `frame_gen_fsr`, `Feature::PsFrameGen`); the choice made in the game menu is learned from the run's `Frame generation setting:` line. `--user-id` for the Local player (Bloodborne). Compatibility: `psport --list-compat` read once per prepared port; broken warns, unsupported hides Play. Bloodborne's built-in patches ship in `bbport/builtin_patches.rs`, handed over as `PS_BUILTIN_PATCHES_DIR` (`--builtin-patches-dir` for psport.exe) and seed a title's own patches folder.
- Dumps: Add dump by copy or move (`library::inspect` reads `param.sfo`/`param.json` capped at 1 MiB and requires `eboot.bin` for a game), by dropping the folder; a dump loose in a games folder's root is renamed into `games/<TITLE_ID>/` on rescan.
- Windows: psport's Windows package from its releases (`psport-windows-<tag>-x86_64.zip` and `.sha256`, `os::windows::package`, `PsDownloads`), or a build of psport's branch with a pinned toolchain (`os::windows::winbuild`: llvm-mingw, CMake, Ninja, `toolchain-win32-1`, MinGit 2.56.0.4, SHA-256 pins re-hashed before each build, Job Object, clean environment, 20 min bound on the toolchain check); `PsSection`, `PsBuilds`, `PsDownloads` and `PsPlay` are `Available`; `PsOnline` is not offered. Mods link with junctions (`platform::link_dir`); `patches/` travels with the build; `Launch::stop_file` is created first on stop, then the job is killed after the grace; `KILLED_EXIT_CODE = 0xDEC00001` marks a run decanter killed, which is no longer a failure in Fallos when the user stopped it. Offline-expected calls are counted apart from failing ones.
- Logs: the Log tab gains Performance and Imports tabs (`metric_lines`, per-title imports psport does not cover from the run's call report, log read at most 64 MiB); DETENER shows from the moment a launch starts and ends the launch's task and port job.
- Ports on Linux: `os/linux` holds the nix toolchain machinery, and `crates/nix` (`decanter-nix`) the toolchain, nix-portable, validation layer and nixpkgs pin; CMake caches naming a collected store path are reset; a tampered toolchain offers Download again.
- Deleting builds, packages and the toolchain asks first (`confirm_panel`).

- Raven (`Runner::Raven`, `Feature::Raven`, Linux x86_64, `Testing`): off until `raven_enabled`, built from `RAVEN_COMMIT` `3179949f14330f14407a41cc923dc902b5aa2bb8` (or its branch's newest commit after a `git ls-remote` on the owner's press, with confirmation) in its own nix recipe with OpenSSL; programs start with `--execution=native` in their own prefix (`docs/raven.md`).

## app

- Downloads view grouped like Steam (Descargando, En cola, En pausa, En curso en otro proceso, Con errores) with Pausar, Reanudar, reorder (drag, Subir/Bajar/al principio/al final), Cancelar with the size it deletes; Reanudar after disk full or a missing library; auto-resume at start (`resume_downloads_on_start`); "Verificar ahora" after a crash; Almacenamiento lists staging folders with no journal; uninstall names each paused download of the game and DLC.
- Install dialog always opens (also from the context menu) and loads branches and languages; language picker at install and an Idioma tab in Propiedades with a "Use this language" button for games installed with every language.

- Reports and clipboard: `redact::outgoing` scrubs the attachment (bearer tokens, JWTs, secret pairs, URL userinfo and queries, account ids, friends' NPIDs, IPs, MACs) and counts are shown before sending; the Fallos and log copy buttons scrub; debug-folder copies pass `redact::text`; server addresses with userinfo or a query are refused.
- Self-update: an AppImage in a read-only folder installs releases into decanter's own copy (minisign-checked) and hands over to it while newer; update texts never ask for a manual download.
- On quit, every psport job (build, game) is stopped and what outlives 3 s is killed; the library fetch loops are waited for before the runtime drops. Once a minute the log records resident, anonymous and file-backed memory and the artwork cache kept.
- Performance: the library is ready once listed, not once enriched; the library is resolved once per pass over cached games; `Db::open` skips the migration at `user_version`.
- A hint in Registro when a short Proton session shows `winewayland.drv` answering `NtUserChangeDisplaySettings` with -2.

## report and reports-server

- `decanter-report`: closed allow-list schema (`SCHEMA = 2`), `scrub_log`, a public clean log derived from a raw one (only lines the vocabulary matches, as template and slots); `PS_FAULT_DUMP` blocks are dropped from logs.
- `decanter-reports`: receives reports on `POST /v1/reports` (64 KiB cap), re-validates with the same crate, publishes at once; partitions `decanter/` and `psport/` (ids start with `d` or `p`) and `accounts/`, each its own encrypted s3db store; public clean log at `/r/<id>/log`; `/admin` with sessions (`__Host-session` cookie, CSRF, same-site `Origin`), roles `viewer` and `admin`, keys `drk_<id>_<hex>` stored as SHA-256 and re-read every 15 s, audit log at `/admin/audit` (swept after `audit_retention_days`, 180 by default); private log viewer, search and diff at `/admin/logs`, `/admin/logs/search`, `/admin/logs/diff`.

## Compatibility

- Breaking: the reports server admin key and report schema 2, above; both are for components new in this range.
- Stored data is extended and migrated in place: `game_language`, `user_version = 2`, the `Language` manifest key, the journal and queue files under `downloading/`, `secrets.bin`, per-game settings under `<library>/psport/` (copied from the shared files after a backup, which are left for older ports), and file modes narrowed on Unix. An older decanter still reads `layouts.json` and the shared PS settings; it does not read the per-game files.
- `libraries.toml` and the GOG session JSON keep their shape. The CLI only gains commands and flags, and `ps run` and `ps prepare` use exit code 2 for "not started".
