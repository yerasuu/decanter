# v0.3.0

Range: `v0.2.0`..`v0.3.0`.

## Breaking

- Stored data moves into each library: `decanter_core::bootstrap::db_path` is `<root>/decanter/decanter.db`, art cache `<root>/decanter/art/`, `umu-run` `<root>/decanter/bin/umu-run-<version>` (`decanter_runtime::umu_run_path`), logs `<root>/decanter/logs/`.
- Outside the library only `~/.config/decanter/libraries.toml` (`known`, `active`, `profile`), the per-game links in `~/.local/share/applications/decanter/` and `decanter.lock` in `$XDG_RUNTIME_DIR`.
- `decanter_core::migrate::run`: one-time move of `~/.local/share/decanter/links.db` into one database per library root, each holding only the profiles whose library it is; runs only while `libraries.toml` is missing, copies through `.tmp` files, checks `integrity_check` and row counts (`OWNER_TABLES`, `PROFILE_TABLES`), and commits by writing `libraries.toml`; `Outcome::Postponed` while another decanter, a game it started or a library's disk is missing.
- The old folder is never written beyond a `MIGRATED-TO` note; builds before 0.3.0 keep reading it and don't see later changes. Deleting `libraries.toml` returns to it; `migrate::remove_legacy` (Ajustes > Almacenamiento) deletes it, keeping any library root inside it.
- GOG install staging moves from `~/.local/share/decanter/staging/` to `<root>/downloading/<profile>/<game>` (`gog::install::staging::staging_root`).

## app

- `views::shell`: Ajustes is a nav section; adding profiles and switching library move into it; the first-run screen picks the UI language.
- `core::switch_library`: the switcher lists every library in `libraries.toml` with its profiles (`core::profiles_by_library`); refused while a game runs or installs.
- `logs`: tracing to stderr and `<root>/decanter/logs/decanter-YYYY-MM-DD.log`, rolled at the UTC day (`DAY_CHECK = 60 s`), `KEEP = 14` files; lines before the library is known are buffered and written first; errors logged as typed values with named fields, in English.
- `gog::without_secrets`: GOG client secret, refresh token and login code stripped from logged errors.
- Running games marked in the Biblioteca and PS sidebars.

## cli

- Global `--library <root>` (absolute path only) and `DECANTER_LIBRARY` override `libraries.toml` for one run (`bootstrap::set_override`); the migration runs before any subcommand.

## library

- One library across several folders: extra roots in table `profile_libraries (profile_id, path, added_at)`; each game whole in one folder; folders added, removed and picked for installs in Almacenamiento; `relocate::move_game` moves files, prefix and manifest between them; offline folders reported (`core::offline_library_folders`).
- `external::launchers`: games installed by HoYoPlay (`HOYOPLAY_GAMES`, registry `HKCU\Software\Cognosphere\HYP\1_0\<biz>`) and GRYPHLINK (`Endfield.exe`, `Arknights.exe`) inside an external game's prefix offered as their own entries sharing it.
- `run_log`: each Proton game's whole output in `<root>/decanter/logs/`, shown in the game's Registro tab.
- Moving a library re-points `libraries.toml`, profiles, desktop entries and symlinks (`bootstrap::relocate`, `taskbar::relocate`).

## runtime

- `decanter_core::scope::own_scope`: each game, PS ones too, starts in `app-decanter-decanter.game.<key>-<n>.scope` via `systemd-run --user --scope`, described with the game's title.
- `closing`: Select + Start held `HOLD = 2 s` on any `/dev/input` pad, or KGlobalAccel action `close-game` (default Ctrl+Shift+F4), closes the newest running game after a notification and `GRACE = 5 s`; setting `close_game_shortcut` (on by default) in Ajustes > General.
- Killed runs logged with their signal and `(core dumped)` (`run_log::describe_exit`).

## desktop

- `taskbar`: per-game entry `<root>/decanter/desktop/game.<key>.desktop` and icon `<root>/decanter/icons/<key>.png`, linked from `~/.local/share/applications/decanter/`, matched by `StartupWMClass` `decanter.game.<key>`; `Exec` runs `decanter --library <root> launch` (through `$APPIMAGE` when set).
- PS windows carry `SDL_APP_ID=decanter.game.ps_<title id>`; icons remade only when the art changed; links owned by another library left alone; stale entries swept at start (`taskbar::sweep`).

## i18n

- `rust-i18n` 4.2.4, texts in `app/locales/*.yml` (`es`, `en`, fallback `es`); `i18n::Language::{Es, En}` from setting `language`, else `LC_ALL`/`LC_MESSAGES`/`LANG`; switched live (`i18n::set`).
- Every view translated; Spanish texts in Spain Spanish; logs, run logs and `failures.jsonl` stay in English.

## ps

- PS4 port is psport (`port::Port::Bbport` upstream `https://github.com/yerasuu/psport.git`); existing checkouts get their `origin` set to it.
- `channel::Channel::{Release, Testing}` per library (setting `psport_channel`, default Release): Release stays on the tag `latest-release` names and fetches its build from the Nix binary cache (`Port::binary_cache`, `DECANTER_PS_BINARY_CACHE` override, GC root `toolchain/prebuilt/<port>`), lookup timeout 20 s, else builds; Testing follows `develop`.
- `updater`: follows upstream `develop`, else its default branch; local commits are those no origin branch or tag holds, so rewritten history kept in an archive tag resets on its own; tags fetched with `--tags --force`.
- `bbport::Names::{Psport, EarlyPsport, Bbport}` told apart by `run.sh`: `PS_*` variables, `out/psport`, `out/psport-gpu-capabilities`, `psport.ini` (seeded once from an existing `bbport.ini`), with `BB_*`, `out/bb-probe` and `bbport.ini` kept for older tags.
- Mods, patches and effects listed by `out/psport --list-mods`, `--list-patches`, `--list-effects` (`bbport::effects`), old paths for older tags.
- Settings: mouse group (`game_mouse_sensitivity`, `mouse_look`, `mouse_sensitivity`, `mouse_invert_y`) in the port's ini; `MEMORY_MODEL_SETTINGS` (`pc_model`, `preupload`, `as_0_3`) hidden and not passed when `run.sh` has a single memory model; `pc_model` off no longer passes `PC_MODEL=0`.
- `PS_MENU_LANGUAGE` from decanter's UI language; ini `menu_language` dropped when it changes.
- `learned`: a `frames no longer overlap (PS_SUBMIT_AHEAD 0)` line is kept per title in `bbport/learned.json`, and later runs start with `SUBMIT_AHEAD=0` until Olvidar.
- Non-Bloodborne PS4 titles run as `Status::Experimental` with `SKIP_GAME_CHECK=1`, `PERMISSIVE=1`; `Status::NeedsVr` (`ATTRIBUTE` bit 26) can't start; `sys_modules_dir` dump optional, passed as `SYS_MODULES`.
- `toolchain`: a host that fails to configure a port is refused (`Toolchain::refuse_host`) and nix builds it; host check requires `freetype2`; builds stamped with the full commit hash; `cmake_cache::forget_moved` drops CMake caches from a moved checkout.
- `run_log`: each job's whole output in `psport/logs/`, `# key: value` header (build, job, target, command, environment) and footer, `KEEP = 30` per kind and target; port's `CALL_REPORT` beside it.
- `failures`: `Kind::Missing` from the call report (unimplemented, stub, failed, expected `status` counted apart); fatal `STOP:` kept as `Kind::Stop`; failures go to the library the game started from; same-second run logs no longer overwrite each other.
- Right-click menu on PS rows and covers: play, details, merge, log, folder, title ID; a second JUGAR is ignored.

## toolchain

- `.github/workflows/ci.yml`: `cargo fmt --check` and `cargo clippy --workspace --all-targets` on every push; on `v*` tags builds `scripts/appimage` and publishes `Decanter-x86_64.AppImage` with `tag-changelog/<tag>.md` as notes.
- `decanter_core::RELEASE_NOTES` `include_str!`s `tag-changelog/v<version>.md`: the build fails without it; `decanter_core::BUILD` is `<version> (<12-char commit>)`.
- Clippy `panic`, `expect_used`, `unwrap_used`, `unreachable`, `todo`, `unimplemented` at deny.
