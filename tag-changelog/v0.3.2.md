# v0.3.2

Range: `v0.3.1`..`v0.3.2`.

## Windows (testing)

- Builds and starts on Windows and macOS (decision #439): `decanter_core::platform::{linux,macos,windows}` hold the folders, runtime lock, free space, migration's process check, Steam roots, links and modes; `decanter_ps::platform` the process groups and signals; `app/src/platform` the close-game watch (`CloseWatch`), tray, detached spawns and exit signals. `nix` and `zbus` build only for Linux. CI job `check-other` (`windows-latest` `x86_64-pc-windows-msvc`, `macos-latest`) runs with `continue-on-error`; the Windows build is a CI artifact (`decanter-windows-x86_64`), not a release asset.
- `decanter_core::capabilities`: `Feature` (18 entries, `Feature::ALL`) with `Support::{Available, Testing, Unavailable(Reason)}` per OS from `platform::support`, narrowed at start by `Capabilities::detect` (systemd, AppImage, StatusNotifier host, MangoHud layer, `gamemoded`); `app/src/capabilities.rs` `Caps` gates views (`gate`, `gate_or_reason`) and marks `Support::Testing` with the "en pruebas" badge (`testing_badge`). Windows: `Play`, `ExternalInstaller`, `GalaxyHook` (x86_64 only) are `Testing`; Proton, prefixes, tray, pad close, desktop entries, scopes, self-update, Steam export, the PS section and the game tools are unavailable.
- Native launch: `decanter_runtime::native::{Launch, prepare, start, Session}` runs the executable from its folder (`CREATE_NO_WINDOW`), with the same run log, playtime and stop (`STOP_POLL_INTERVAL = 2 s`, `POLITE_STOP_ATTEMPTS = 5`); `app/src/launch/{native,proton}.rs` are the per-OS backends, `cfg(proton)` (from `app/build.rs`, `crates/runtime/build.rs`) compiles the Proton one. GOG save paths resolve to the user's own folders (`gog::save_location`); stored Proton fields stay readable and are ignored.
- DirectX 7 hint: a native session ending with a failure status reads the executable's PE imports (`app/src/launch/pe.rs`, cached per path, size and mtime); importing any of `DX7_IMPORTS` (`ddraw.dll`, `d3dim.dll`, `d3dim700.dll`) writes `DX7_HINT` to the run log and the Registro tab, suggesting a DirectDraw wrapper (decision #516).
- External installer: the external-game form's installer button runs the `.exe`, or `.msi` through `msiexec /i`, with `powershell.exe` `Start-Process` so UAC can elevate it, waits, then opens the executable picker in Program Files (`app/src/external/mod.rs`, `views/external/form/installer.rs`).
- Galaxy proxy: `crates/gog/build.rs` builds `decanter-hook` for the Windows target and `gog::hook` deploys it beside the game where `GalaxyHook` is offered and `cfg(galaxy_hook)` built it; unlocks go to `<root>/decanter/decanter-hook-<account>-<game>.jsonl` (`DECANTER_PRODUCT_ID`, `DECANTER_ACHIEVEMENT_LOG`).

## app

- `self_update`: AppImage-only (`APPIMAGE` set, not in the nix store) install of decanter's GitHub release (`releases::DECANTER_REPO` `yerasuu/decanter`) after verifying `Decanter-x86_64.AppImage.minisig` against the embedded `keys/release.pub` (minisign key `F66D47DF5B155894`) and its trusted comment `decanter vX.Y.Z`; downloads only from `DOWNLOAD_HOSTS`, capped at `MAX_APPIMAGE = 512 MiB`; restarts after quit. Ports, `umu-run`, nix-portable and UMU-Proton are checked against their remotes on demand (Ajustes > General / Compatibilidad).
- Theme: `theme::RADIUS` 3 -> 6, `RADIUS_SM` 2 -> 4, new `RADIUS_LG = 10` for menus, dropdowns and dialogs; progress bars are pills; `theme::compact_row`, `theme::card` and `widgets::hero_stat` shared by the PS section.
- Unlock times and dates follow the UI language and local time zone; GamesDB's 0-100 score shows as `75/100` (`views::library::fmt`).
- Sidebars: rows that can't be played now use the muted text colour instead of the installed and ready dots; running keeps green and ▶.

## runtime

- MangoHud: `decanter_core::game_tools::GameTool::MangoHud`, global default and per-game override in table `game_options (game_key, option, enabled)`; `mangohud_env` sets `MANGOHUD=1` and `MANGOHUD_CONFIG` (logs in `<root>/decanter/logs/mangohud/`, autostart setting `mangohud_autostart_log`); offered only when the implicit Vulkan layer is found.
- GameMode: `GameTool::GameMode` the same way; `gamemode_prefix` registers the launch's pid with `gamemoded -r` from a shell that then execs it, since `gamemoderun`'s `LD_PRELOAD` is cleared by umu under gamescope; offered only when `gamemoded` or `com.feralinteractive.GameMode.service` is found.

## ps

- Release ports run from psport's bundle: `decanter_ps::bundle` downloads the tag's `psport-<tag>-x86_64.tar.zst`, checked against its published SHA-256 (`MAX_BYTES = 512 MiB`, `REQUIRED` files), into `<library>/psport/ports/bbport-bundles/<tag>` before resolving any toolchain, so hosts without nix don't fetch nix-portable; older tags keep the nix cache; `DECANTER_PS_BUNDLES` overrides the source.
- Build fallback: `decanter_ps::builds::Record` (`<library>/psport/ports/<port>-builds.json`) keeps the last commit that built and the failed ones; a failed build after the checkout moved goes back to the last good commit and builds there; automatic updates skip the failed commit until a retry.
- Capabilities from psport: `bbport::features` runs `out/psport --list-features` once the port is ready, checks the JSON (`MAX_ANSWER = 256 KiB`, `MAX_FEATURES = 256`) and maps it onto `PsPlay` and `PsMenuBinding` (`port_menu_binding`); ports without it report nothing.
- Aspect ratio: with `aspect_ratio` on `auto` or absent, `state::ps::play::display_aspect_ratio` maps the display GPUI reports to the nearest of `4:3`, `16:10`, `16:9`, `21:9`, `32:9` (`bbport::nearest_aspect_ratio`) and passes `PS_ASPECT_RATIO` to ports that read `psport.ini` (decision #510).
- MangoHud and GameMode apply to PS runs too (`decanter_ps::process`).
- Frame stats: per-game setting `frame_stats` starts the game with `PS_FRAME_STATS=1`; `decanter_ps::frame_stats::RunStats` reads the run logs back into the Registro (`views/ps/games/runs.rs`): average FPS, estimated 1 % low, frame time range, pipeline-compile stalls, an FPS chart and the change from the previous run.
- Gamepad editor (`views/ps/games/gamepad/`): list or line-art pad with button and action rows around it (setting `ps_gamepad_mode`), Juego/Port tabs, edits staged until Aplicar (`staged.rs`); shipped layouts are read-only, a user's own keeps its `PadLayout::template` and `restore` goes back to it.
- Keyboard: each action shows its in-game meaning, the gamepad screen's texts, with moving and the camera for the sticks.
- Port menu: Teclado and Mando bind psport's `key.menu` and `pad.menu` (L3+R3 and Insert stay built in), offered only with `PsMenuBinding`.
- PS section aligned with the app's theme: settings cards on `compact_row`, keyboard groups on `card`, the log and failure output as rounded panels.
