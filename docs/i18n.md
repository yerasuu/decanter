# UI languages

Texts live in `app/locales/<code>/<area>.<code>.yml` (flat `key: value`), loaded by
`rust_i18n::i18n!` in `app/src/main.rs`. A language is a folder: adding one needs no Rust change.

## Adding a language

1. Create `app/locales/<code>/` with one file per file of `app/locales/en/`, named
   `<area>.<code>.yml`, plus `_language.<code>.yml` with `language.native_name` (the name in the
   language itself) and `language.label` ("Language" in it).
2. For a machine-translated language, add `language.machine_note` to `_language.<code>.yml`: one
   sentence in that language saying the translation is automatic and may contain errors. Reviewed
   languages (en, es) leave it out. The key drives the UI: the picker marks the language with `*`
   and Ajustes and the first-run screen show the note under the picker while it is selected.
3. `scripts/i18n-check <code>` must print `0 problems`.
4. CJK languages (`zh-CN`, `ja`, `ko`) also need their entry in `cjk_families` (`app/src/theme.rs`);
   the bundled Inter, Oswald and JetBrains Mono cover Latin and Cyrillic but not CJK.

The code is the folder name: `pt-BR`, `zh-CN`, `ja`. The picker lists `en`, `es`, then the rest by
native name.

## Fallback

A key a language lacks is looked up in English, then Spanish (`fallback = ["en", "es"]`; rust-i18n
also tries the language without its region first). With debug logging, a key reached through `Text`
that the current language lacks is logged once as `translation missing, using the fallback language`.

## System locale

With no language chosen, the system locale picks one: exact tag, then its language, then any folder
of that language (`pt`, `pt_PT`, `pt_BR` to `pt-BR`; `zh`, `zh_CN`, `zh_Hans_CN`, `zh_SG` to `zh-CN`).
Traditional Chinese (`zh_TW`, `zh_HK`, `zh_MO`, any `Hant`) gets English, not Simplified.
Anything unmatched gets English.

## Placeholders

`%{name}` markers are code arguments: a translation keeps exactly the same set as the English string,
any order, none renamed or translated. `common.date.time` is the exception (it may use any of
`hour12`, `hour24`, `minute`, `meridiem`).

## Check script

`scripts/i18n-check [code...]` compares each folder of `app/locales` (all but `en` by default) with
`en` and exits 1 on missing keys, extra keys (except `language.machine_note`), empty values,
duplicate keys, multi-line values, or placeholders that differ. `I18N_LOCALES=<dir>` points it
elsewhere. Run it before committing any locale change.

## New strings

A new key goes to `en` and `es` always, written by hand (Spanish from Spain, tuteo). For the
machine-translated languages, run `scripts/i18n-check`: its "missing key" list is what to translate;
until then they fall back to English.
